# Autonomy Policy — 無人值守執行規則書

> 使用者會在睡覺時讓 agent 連續執行多個里程碑。這份文件界定：
> **可以自己決定什麼、必須停在哪裡、停下來要留什麼。**
> 決策依據 [ADR-012](decisions.md#adr-012)。里程碑的值守標記在 [PLAN.md](../PLAN.md)。

---

## 0. 一句話總則

> **跑到底，任何驗證失敗即停。**
> 不得降低標準、不得跳過、不得「先繼續之後再回來修」。
> 停下來寫一份 handoff 報告，比硬跑出一堆不能用的結果有價值得多。

---

## 1. 執行迴圈

```
讀 CLAUDE.md / PLAN.md / worklog 最後一筆 / decisions.md
  → 找出第一個未勾選的里程碑
  → 檢查它的值守標記
        🙋 → 停，寫 handoff，結束
        🤖 / 👀 → 繼續
  → 跑 §2 的 preflight
  → 執行該里程碑
  → 跑 PLAN.md 該里程碑的「驗證」欄，逐項記錄通過與否
        任一項失敗 → 停，寫 handoff，結束
  → 👀 的話：用 Read 工具打開產出的圖自己檢視；明顯不合理 → 停，寫 handoff
  → 全綠 → 勾選 PLAN.md → 追加 worklog → 建該階段 skill → git commit
  → 回到迴圈開頭
```

**每個里程碑結束都要 commit。** 過夜跑到一半失敗時，前面成功的部分必須已經在 git 裡。

---

## 2. 每個里程碑開始前的 preflight

M4 之後由 `df-guard` skill 執行；在它建立之前逐項手動確認。

| 檢查 | 失敗時 |
|---|---|
| `splits/split_manifest.json` 的 SHA256 == `splits/MANIFEST.sha256` | **停**。有人動過凍結的 split，不准自行修復 |
| 本里程碑要讀的所有影像路徑，SHA256 都不在 `splits/test_blocklist.json` | **停**。這是紅線 |
| `data_root` 所在磁碟剩餘空間 > 預估需求 × 1.5 | **停**，回報需要多少 |
| GPU 可用、VRAM 足夠 | **停** |
| 沒有把 `.env` 內容寫進任何檔案 | **停** |
| 前一個里程碑已 commit、`git status` 乾淨 | 先 commit 再繼續 |

## 3. 可以自己決定的事

- **門檻校準**：pHash 閾值、`τ_low` / `τ_copy`、過濾各道的門檻、聚類 k 值
  → 但**校準過程與最終值一定要寫進對應報表**，不准偷偷改了不記錄
- **暫時性錯誤的重試**：網路逾時、HF 下載中斷、CUDA OOM 後降 batch size 重試
  → 同一步驟**最多重試 3 次**，第 3 次仍失敗就停
- **瑕疵型別的暫用命名**：自動產生 `<pcb1-type0>`、`<pcb1-type1>`…並繼續往下跑。
  **不要停在這裡等使用者命名**。使用者事後只改**顯示名稱**（`type_name`），
  **不動 `trigger_token` 字串**，所以不需要重訓
- **實作細節**：函式拆法、資料結構、日誌格式 —— 只要不違反 [interfaces.md](interfaces.md) 的 CLI 契約
- **產出圖表的樣式**：配色、排版、字體大小

## 4. 必須停下來等人

| 情況 | 為什麼 |
|---|---|
| **任何一項驗證失敗** | 總則 |
| **需要花錢** | 一律先問 |
| **>2GB 下載** | [CLAUDE.md](../CLAUDE.md) 規則（VisA 1.80 GB 未達門檻，但 M2 仍標 🙋 因為它是第一次大量寫入磁碟） |
| **Colab 訓練** | agent 碰不到 Colab |
| **任何 `git push` / HF upload / 轉 public** | 對外動作 |
| **磁碟不足或 GPU 不可用** | 環境問題 |
| **同一步驟重試 3 次仍失敗** | 不是暫時性錯誤 |
| **產出的圖目視明顯異常**（ROI 抓在背景上、生成圖全灰、mask 全零…） | 硬跑下去只會浪費整晚 |
| **要修改任何已凍結的檔案**（`split_manifest.json`、`defect_types.json`、`source_checksums.json`） | 凍結就是凍結 |
| **要偏離 [decisions.md](decisions.md) 的任何 ADR** | 改 ADR 是使用者的決定 |
| **要新增沒寫在 [interfaces.md](interfaces.md) 的 CLI 參數或改變既有語意** | 契約要先更新 |

**停下來的方式**：寫 handoff 報告 → `git commit` 已完成的部分 → 結束回合。
**不要**在停下來之後繼續嘗試別的路線。

## 5. Handoff 報告

路徑：`reports/handoff/<YYYY-MM-DD>.md`（同一天多次就加 `-2`、`-3`）

```markdown
# Handoff 2026-08-05

## 結果
跑到：M9（M1–M8 全綠並已 commit）
狀態：**停在 M9**
原因：驗證失敗 —— mask placement 的 ROI 有 37% 落在背景上（門檻是 0%）

## 完成的里程碑
| M | 標題 | commit | 驗證 | 耗時 |
|---|---|---|---|---|
| M1 | uv 環境 | a1b2c3d | 全綠 | 6 min |
| ... |

## 停下來的細節
- 失敗的驗證項：`placement mask 100% 在 legal ROI 內`
- 實際數值：pcb1 63% / capsules 71%
- 我已排除的可能：（列出試過什麼、結果如何）
- 我沒有動的東西：（明確列出，讓使用者知道現場沒被弄亂）

## 需要你決定
1. ROI 偵測改用 DINOv2 前景分割為主（Otsu 當 fallback）？我傾向這個
2. 還是放寬 containment 門檻到 95%？我不建議，那會讓合成瑕疵貼到背景上

## 產出物
- `reports/figures/placement_check_pcb1.png`（我看過，ROI 明顯抓到背景的桌面）
- 完整日誌：`reports/handoff/2026-08-05_log.txt`

## 花費
本機 GPU 時數 X 小時；Colab 未使用；無金錢花費。
```

報告要求：
- **失敗原因寫具體數值**，不要只寫「驗證沒過」
- **列出「我沒有動的東西」**，讓使用者知道現場狀態
- **給 1–3 個選項並說出你傾向哪個**，不要只丟問題
- 附上要看的圖的路徑

順利跑完的情況也要寫 handoff（狀態改成「完成到 M14」），並照慣例附「換你做」清單。

## 7. 誠實性紅線

無人值守最大的風險不是跑不完，是**跑出看起來完成、實際上是假的結果**。以下一律禁止：

- ❌ 驗證沒過卻勾選 PLAN.md
- ❌ 為了讓驗證通過而放寬門檻**卻不記錄**
- ❌ 跳過「自己看圖」這一步，只確認檔案存在就當完成
- ❌ 從 notebook 畫面或日誌抄數字，而不是從 raw 檔重新聚合
- ❌ 因為合成資料沒有提升就改用別的指標重畫，直到看起來有提升
- ❌ 修改凍結的 split／型別檔讓結果變好看
- ❌ 用 `2cls_fewshot` 的 test 評測（會洩漏一半測試瑕疵，數字會很漂亮但是假的）

早上被抓到一個假結果，會讓其他所有結果都失去可信度。**寧可停在 M7，也不要假的 M14。**
